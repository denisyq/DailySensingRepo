广电总局令第 17、18 号发布：智能电视须「开机看全屏直播」、禁开机广告、遥控器一键切直播

发布日期 2026-10-27 · 施行日期 2026-11-27 · 来源：中国政府网 / 央视网《新闻1+1》/ 腾讯新闻 / 中国新闻出版广电报（多方转载整理）
国家广播电视总局发布《有线广播电视运营服务管理规定》（令第 17 号）与《交互式网络电视运营服务管理暂行规定》（令第 18 号），两条均自 2026-11-27 起施行。硬性条款包括：运营方须坚持「直播优先」原则、实现开机看全屏直播、设置频道回看入口、不得播放开机广告；智能电视机应支持优先呈现直播频道功能并提供便捷设置入口，由用户自行选择开机进直播或进电视交互主页；交互主页的页面、导航栏、状态栏、推荐位须符合主管部门要求；首页须设免费专区并重点推荐优质免费内容、精简收费栏目数量、明示节目收费信息、规范应用专区运营与订购支付管理；须不断优化终端性能「缩短开机时长」，并简化遥控操作、实现遥控器一键切换直播信源；鼓励语音遥控、手机遥控与 AI 提升体验。服务侧另要求城镇故障 24 小时内修复、重大故障 48 小时、农村或交通不便地区 72 小时，用户投诉 10 个工作日内答复；违规可责令改正、警告、通报批评直至罚款。央视评论指出「直播优先」实质是把第一选择权让给公共服务内容，压缩开机广告与付费包入口。
产品影响：距施行仅 28 天，中国区在售与在研机型的启动链路、首页结构、付费区透明度、遥控器键位映射四项均需在到期前完成合规评估；「快捷设置入口 + 用户自选」意味着不能只做一次性 OTA 硬切，需要可回退的引导与设置项。建议立即拉通 TV SW、UX、法务与市场监管做差异清单。

Netflix 宣布 2027 年推出「短片/Shorts」主题分类，同期裁员约 6%、管理层换帅

2026-10-26 宣布 · 来源：虎嗅网 / 搜狐（经转载整理）
Netflix 于 10 月 26 日宣布 2027 年将推出主题「短片」分类，以及更多按类型、情绪或兴趣组织的细分内容，继 2026 年 4 月上线的竖屏推送功能 Clips 之后继续加码短内容。但联合 CEO Ted Sarandos 在三季度财报会上称约 95% 支出仍集中在核心业务，短视频、第三方与 UGC 处于早期探索且投入受限；股东信罕见承认「投资者对观看时长增长有些担忧」。同期公司宣布裁员约 6%（近 1000 个岗位），为近年最大规模；电影部门主管 Dan Lin 与首席内容官 Bela Bajaria 相继离职。外部数据显示：Omdia 称 2025Q4 用户日均在 ReelShort 停留 35.7 分钟，高于 Netflix 的 24.8 分钟；Sensor Tower 称 2026Q1 全球短剧应用下载量突破 8.5 亿次、同比 +140%。
产品影响：竖屏/微剧正在从「移动端现象」变成 CP 的内容结构变量，TV 端若要承接需在首页给出「短内容聚合位 + 竖屏 9:16 的安全区渲染策略」，否则大屏只是被动承接长视频的价值外溢；同时 CP 削减非核心投入，意味着 TV 端新功能的联合验证资源会变少，排期需留冗余。
来源：虎嗅网 · 《Netflix 的中年危机》 · 搜狐（同源转载）

YouTube 官方博客（10-28）公布客厅增长方法论：智能电视日观看超 10 亿小时，Shows / Multiview 成打包形态

2026-10-28（MIPCOM 2026 期间） · 来源：YouTube Blog，经 NBK Social 转述（经转载整理）
YouTube 在官方博客发文列举媒体公司做大受众与收入的五种做法，核心数据为：每天有超过 10 亿小时的 YouTube 内容在智能电视上观看。五种做法包括多元收入（广告分成 + 直接售卖优质广告位 + Channel Memberships + 自动配音出海 + Content ID）、完整剧集与档案内容上屏（France Télévisions 旗下 franceinfo 仅 9 月即 1.1 亿次观看、订阅破百万；荷兰《Fabeltjeskrant》上线修复并配音的 1600+ 集）、用逐秒留存数据试片、与创作者合作（荷兰 NPO 以创作者节目替代引进电视格式）、为客厅做打包——Banijay 与 BBC 用 Shows 功能打包 Mr. Bean、BBC Earth，Coachella 用 Multiview 让观众同时看四路舞台。英国播客厂牌 Goalhanger 今年累计 6300 万观看小时，近四分之一收入来自 Channel Memberships。该文为方法论而非新功能发布。
产品影响：「每天 10 亿小时在智能电视」是客厅优先级的官方背书，可直接用于内部说服素材；Shows 与 Multiview 被点名为客厅打包形态，意味着 EPG/节目集合的数据结构与多路同屏的解复配将成为 CP 对 TV 平台的新验收项，需在 UX 与 SoC 解码能力上预留（见 D 区 AV2/硬解门槛）。

multi-DRM 打包：CMAF 一份切片服务 HLS 与 DASH，CBCS 是唯一可跨 FairPlay/PlayReady/Widevine 的加密模式

2026-10 · 来源：OTT 技术博客（经转载整理）
该文重申：Apple FairPlay 绑定 HLS，Widevine/PlayReady 以 DASH 交付最干净，多 DRM 服务通常同时出 HLS+FairPlay 与 DASH+Widevine/PlayReady；CMAF 可用一套 fMP4 切片同时生成 .m3u8 与 .mpd 清单，降低源站存储与 CDN 碎片；加密模式选择上，CBCS 与 CENC 混用会导致 FairPlay 无法解密「共享切片」，选 CBCS 通常才能保持一份加密资产覆盖三套 DRM。此外 LL-HLS / LL-DASH 可将延迟压到数秒级，但绝对值依赖编码器、分段时长、CDN 与播放器调优。

HTML-in-Canvas API 在 Chrome 157 默认开启，并伴随一轮破坏性更名

2026-10（Chrome 155–157 变更区间）· 来源：html-in-canvas.dev API 参考文档（第三方维护，与 Chrome 发布节奏对照）
文档记载 Chrome 157 起该 API 默认开启并同时移除旧命名：layoutsubtree 变为画布上的 content="drawable" 且每个被绘制元素需带 drawable 属性；drawElementImage() 在 2D 上下文中不再返回值（可删除原先用于同步位置的 element.style.transform = matrix 代码）；WebGL 的 texElementImage2D() 由 texElementSubImage2D(target, level, xoffset, yoffset, element) 取代（需先 gl.texImage2D 分配纹理）；WebGPU 的 copyElementImageToTexture() 更名为 drawElementImageToTexture()；新增 canvas.updateElementGeometry() 用于设置 WebGL/WebGPU 画布的命中测试与可访问性边界。
产品影响：凡用 Canvas 做 UI 合成/动效的 TV Web App（含 Launcher 风格的 Web 实现）在升级到含此版本的运行时时会出现 API 不存在报错；结合 B 区 Tizen 若跟不上到 157，短期内不会在 TV 侧出现，但Web App 代码库现在就该加双面 feature detection。
