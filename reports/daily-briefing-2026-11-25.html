C · 外设与输入

Gamepad API 能力边界梳理（11 月口径）：震动支持矩阵与 DualSense 高级能力缺口

来源：Gamepad Tester Pro（caniuse 数据 11/23 核对）、MDN｜日期：2026-11-23

浏览器 Gamepad API 现状：Chrome/Edge（桌面+Android）支持按键+震动（Chrome 68+），Safari 16.4 起支持震动，Firefox 一般不支持震动；标准映射（Xbox 布局）为主流，第三方手柄 mapping 混乱仍是常态。DualSense 自适应扳机、陀螺仪原始数据不在基础 Gamepad API 内，只能经 WebHID（仅 USB）获取；浏览器无法读取固件/电池/传感器类型。

🟡 值得跟踪已正式发布（现状梳理）Web 平台能力边界
影响：CP 在 TV 上做游戏化交互时，「TV+蓝牙手柄」的基础输入（按键/摇杆）可用而高级触觉不可用；Netflix TV Games 选择「手机当手柄」正是绕开该缺口的务实方案。Tizen 侧若要支撑高阶手柄能力需走平台原生 API 而非 Web 标准。
原文：Gamepad Tester Pro ｜ PS5 WebHID 校准实践

第三方手柄标准化实践：normalize 层与 Playwright 回放测试范式

来源：DEV Community 技术实践｜日期：2026-11

开发者实践显示：非标准手柄在浏览器中按钮序号错乱，需在 navigator.getGamepads 之上做 normalize 代理层统一为 standard mapping，并用 Playwright 注入录制报告做回归；Sony 单一厂商可控，第三方长尾仍无系统性方案。

⚪ 背景参考技术实践输入兼容性

D · 多媒体与 DRM

🔴 低端 SoC 档位 AV1 硬解盘点：MT9681 / S928X-J / RK3576 全线支持，主流 OTT 档位仍是 H.264 优先

来源：IT之家 / ITBear（当贝 X9 Max·MT9681）、番茄科技 SoC 横评｜日期：2026-11-20~24

联发科 MT9681（高端 4K 智能投影/电视平台）支持 H.264/HEVC/AV1 解码 + AI 超分 + 1ms 游戏低延迟，已在当贝 X9 Max 落地；Amlogic S928X-J 支持 8Kp60 AV1，RK3576 支持 4Kp120 AV1；而面向主流 IPTV 的 S905X5M 档位解码上限 4Kp75（H.264/HEVC 为主），AV1 并非标配。联发科称全球 60%+ 电视搭载其芯片。

🔴 重点关注已正式发布SoC 档位AV1 硬解
影响：AV1 已下沉到中高端 4K SoC，但 1–2GB 内存入门档仍以 HEVC 为主——CP 若全面转 AV1 供给（YouTube 已默认），入门机带宽成本与画质将劣化；建议在 E 板块跟踪的入门 SoC 选型中把「AV1 硬解有无」列为 2027 档位划分的正式参数。

Widevine L1 仍是 HD/4K 内容解锁的硬门槛（终端侧实证）

来源：Acciyo 终端评测、Arytech 行业实践｜日期：2026-11

终端评测再次确认：无 Widevine L1 认证的设备在 Netflix/Disney+/YouTube 上被强制降至 480p/HD 档（如平板类产品仍以「L1 认证」为卖点）；行业侧多 DRM（Widevine L1 + FairPlay + PlayReady）打包、边缘缓存密钥、forensic watermarking 已是直播大事件的标准配置。

🟡 值得跟踪现状确认DRM 等级认证门槛
影响：对三星 TV 全系 L1 覆盖不构成新风险，但对 License 机型的认证成本与周期是硬约束；中国区 ChinaDRM/WisePlay 双轨需求不变。
