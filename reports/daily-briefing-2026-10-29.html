WebHID 仅桌面 Chromium（Chrome 89+、Edge 89+、Opera 76+）支持，全球覆盖率约 27–30%；Firefox、Safari、所有移动端以及 Samsung Internet 均不支持；Gamepad API 覆盖率约 97%（含 Safari 10.1+、iOS Safari 10.3+）。WebHID 可取到陀螺仪、触摸板、灯条与自适应扳机（DualSense vendorId 0x054c / productId 0x0ce6，通过 47 字节 output report 配置扳机），这些是 Gamepad API 不予建模的部分。规范仍在 WICG 孵化，未进入 W3C 工作组。
影响：TV Web 游戏与云游戏的高级手柄反馈（力反馈扳机、陀螺仪）在 Web 路径上基本不可用。结论很直接：TV 端应以 Gamepad API 为主路径，把 WebHID 视为不可依赖的加分项，避免把产品需求建立在 30% 覆盖率的 API 上。

AV2：目前没有任何电视支持硬件解码，YouTube 计划 2027 Q1 在 Web 端以软件解码首发

来源：FlatpanelsHD / HiFi.Fan / 中策知识产权研究院 · 2026-10 · 全球
AV2 由 AOMedia 于 2026 年 6 月发布（参与方含 Amazon、Apple、Google、Intel、Netflix、Samsung），压缩效率较 AV1 提升约 30%。YouTube 目标 2027 年第一季度在 Web 端首发，初期使用软件解码；Netflix、Prime Video、Meta 表示探索或支持但未给出时间表。截至 2026 年中，尚无任何在售电视、机顶盒或手机搭载 AV2 硬件解码器，软解算力约为 AV1 的 5 倍。芯片 IP 侧已起步：Chips&Media 于 2026 年 5 月宣布完成 AV2 硬件解码 IP 开发并发布 RTL，正与北美大客户洽谈商用授权；Allegro DVT 的 AL-D5200 多编解码 IP 支持 AV2/VVC/AV1。行业普遍预计 AV2 硬件解码 2027–2028 年进入主流设备，移动端可能要到 2030 年前后。
影响：这是本期对低端机型影响最大的一条：未来 2–3 年内入门 4K 电视不会有 AV2 硬解，而软解约 5 倍于 AV1 的算力在 2GB + 四核 A55 档位上完全不可行。产品规划上应明确"AV2 不在本代入门机型的能力承诺内"，并把 AV1 硬解作为 2027–2028 款型的必备基线。

4K/HDR 的硬件 DRM 门槛：Widevine L1 + PlayReady SL3000 + HDCP 2.2/2.3，缺一即降档

来源：Fora Soft DRM 指南 / Gumlet / Xangshi 硬件认证说明 · 2026 · 全球
4K 与 HDR 内容通常要求 Widevine L1（密钥与解码均在硬件 TEE 内、输出受 HDCP 保护）与 PlayReady SL3000（硬件级，2015 年引入）；MovieLabs 的增强内容保护建议同样指向该硬件档位。Widevine L2 已在实践中被视同 L3；L3 为纯软件、无硬件信任根，通常被内容方策略限制在 SD/540p（这也是 Netflix、Disney+ 在桌面 Chrome 上降到低分辨率的原因）。PlayReady 阶梯为 SL150（软件，仅测试）/ SL2000（软件加固）/ SL3000（硬件 TEE，Samsung Tizen、LG webOS、Hisense VIDAA、Xbox 的出货档位）。1080p 以上还需 HDCP 2.2 或 2.3 的硬件输出通路。L1 需要 SoC 支持 TEE 与安全视频通路、安全启动与密钥烧录、HDCP 2.2 输出，且无法通过后天固件开启。
影响：直接承接上期"入门 4K SL3000 / Widevine L1 实测"跟踪项。入门 4K 机型若未取得 L1/SL3000，Netflix、Disney+ 会按许可策略强制降档，用户看到的"4K 电视放不出 4K"是卖场里最致命的体验落差。建议把 L1/SL3000 列为入门 4K 的一票否决项，并在认证清单中逐机型留档。

2026 封装基准：CMAF fMP4 + CBCS 一套加密服务三 DRM；PlayReady 需 ≥ 4.0

来源：Fora Soft 直播安全指南 · 2026 · 全球
CMAF fMP4 搭配 CBCS 已成为 2026 年的通用交付形态：FairPlay 一直使用 CBCS，PlayReady 4.0+ 与现代 Widevine 均可解密，因此一套 CBCS 封装的 CMAF 可同时服务三家 DRM。仅当设备尾巴包含低于 v4 的 PlayReady 或较老的 Widevine/Android 设备时，才需要保留 cenc（AES-CTR）回退。
影响：Tizen 侧的 PlayReady 版本基线必须在规格书里写死（≥ 4.0 才能吃 CBCS），否则会遇到"内容方只出一套 CBCS、老机型放不了"的兼容性事故。同时需确认 cenc 回退链路是否仍然打通。

多密钥封装与轮换：音轨不走 SL3000 路径，密钥按 4–24 小时轮换

初步业绩：营收约 195 万亿韩元（区间 194–196 万亿），营业利润 107.4 万亿韩元（区间 107.3–107.5 万亿），同比分别 +126.6% 与 +782.5%，为韩国企业首次单季营业利润突破百万亿韩元；前三季累计 254.1 万亿韩元（去年同期 23.5 万亿）。市场预计存储业务营业利润接近 110 万亿韩元（DRAM 约 80 万亿、NAND 约 30 万亿）；DX 部门预计连续第二季亏损（Q2 约 -8000 亿韩元，Q3 预计亏损超 1 万亿韩元）。Q4 一致预期 116.35 万亿韩元。

来源：DISCIEN 迪显（腾讯新闻转载） · 2026-10-25/26 · 全球
2026 年 Q3 全球 Mini LED 背光电视出货 520 万台，同比 +46%，前三季累计接近 1280 万台（同比近 +30%）。TCL 出货 140 万台（+47%）居首，海信 110 万台（+42%），三星 90 万台（+31%）第三；TOP3 合计超 340 万台，占近三分之二份额。技术路线上 TCL 押 SQD 超级量子点、海信押 RGB-LED 直出背光、三星为 OLED 与 RGB-Mini LED 双线并行并主打 micro-RGB 概念。驱动因素为存储与上游原材料涨价挤压整机利润，品牌被迫向高附加值结构调整。

W3C Device Posture API 进入候选推荐草案（2026-10-26），编辑曾代表三星

来源：W3C 官方 TR / MDN 兼容数据镜像 · 2026-10-26 · W3C Devices and Sensors 工作组
Device Posture API 于 2026 年 10 月 26 日发布候选推荐草案，编辑为 Diego González（Microsoft，formerly on behalf of Samsung）。规范定义 navigator.devicePosture 与 DevicePostureType（"continuous" / "folded"）及 device-posture 媒体特性，已在 Chromium 系浏览器实现，WebKit 与 Mozilla 尚未发表正式立场。兼容数据记录 Chrome 132 与 Samsung Internet 16.2 起支持，Safari iOS 27 需开启 DevicePostureEnabled 偏好项。
影响：规范本身面向折叠设备，与 TV 无直接关系；但"三星前编辑 + Samsung Internet 已支持"意味着三星在形态相关 Web 标准上仍有影响力。可作为评估 Device Posture 类能力是否向大屏（如可旋转/分屏形态）延伸的起点。

WebAssembly Web API 2 进入候选推荐草案（2026-10-21/27），定位为常青标准

来源：W3C 官方 TR · 2026-10-21（镜像版本 10-27） · WebAssembly 工作组
WebAssembly Web API 2 发布候选推荐草案，描述 WebAssembly 与更广泛 Web 平台的集成（compileStreaming / instantiateStreaming 等流式编译与实例化、序列化、媒体类型注册）。工作组明确计划将其持续保持在 CR 状态作为"常青标准"更新，而非转为正式推荐。
影响：Wasm 是 TV 端跑软解码、端侧推理与高性能图形的可行路径，流式编译对内存受限设备尤其关键（边下边编译可降低峰值内存）。建议在 TV Web 运行时上验证 compileStreaming 的可用性与内存峰值表现。

Liquid AI LFM3：6 个约 2B 开源模型，4-bit 约 1GB 内存，256K 上下文，视觉 62 项基准均值 71.4

来源：Liquid AI 发布博客及多家转载（i-Scoop / Times of AI / TechBeat / SaaS Sentinel） · 2026-10-27 · 全球
LFM3 家族共 6 个约 2B 参数模型，全部基于 LFM3-1.7B-Base（预训练 22 万亿 token）：LFM3-1.7B（文本，256K 上下文）、LFM3-VL-2B（1.9B，视觉+视频输入）、LFM3-Audio-2B（18 语种）、LFM3-Omni-2B（2.2B）、d1-2B 与 d1-Omni-2B（决策模型）。关键工程数字：文本模型 4-bit 下约 1GB 内存；128K 上下文时 KV cache 需 1.6GB（对比 Qwen3.5-4B 4.3GB、MiniCPM5-2B 5.6GB），连同权重在内仍控制在 3GB 以内。架构为 24 层三混合（13 层门控短卷积 + 5 层 256-token 滑动窗口注意力 + 6 层全局注意力），经 14 种设备/后端组合调优（含手机、树莓派 5、Qualcomm Hexagon NPU）。视觉模型 62 项基准均值 71.4（Gemma 4 12B 为 71.7）；文本模型 WebArena-Verified 38.42。许可为 LFM Open License v1.0，商业使用限年收入低于 1000 万美元的组织。
影响：直接对标上期"端侧 AI 指标化"跟踪项：1GB 权重 + 1.6GB KV cache 是当前端侧小模型的现实水位。对照入门 TV 的 2GB 总内存，结论明确——通用端侧多模态大模型在 2GB 机型上不具备可行性，TV 端侧 AI 必须走专用小模型（画质/语音/字幕等单点任务）路线，且需为 NPU 预留独立内存预算。

端侧推理的 Web 路径：Wasm Web API 2 流式编译 + JSPI 是 TV 上运行小型模型的现实约束

来源：基于 W3C WebAssembly Web API 2 CRD 与 Interop 2026 焦点项的推导 · 2026-10
在 TV Web 运行时上承载端侧推理，实际依赖两条链路：一是 Wasm 模块的流式编译与实例化（WebAssembly Web API 2，2026-10-21 CRD），二是 Wasm 与异步 JS 互操作的 JSPI（JavaScript Promise Integration，被列入 Interop 2026 焦点领域）。后者决定 Wasm 侧能否直接调用平台的异步能力（如 NPU 调度、模型加载）。
影响：若 TV 端侧 AI 功能需要通过 Web 应用交付（而非仅原生应用），需要先确认 Tizen Web 运行时对 Wasm 流式编译与 JSPI 的支持情况。这是把"端侧 AI"从营销话术落到可实现清单的关键前置检查项。
